The package `@harbourline/router` is shared by a storefront's pages. The uncommitted change adds `src/params.ts`, which parses route patterns at the type level with `Split`, `ParamFromSegment`, `UnionToIntersection`, `Merge`, `ExtractParams` and `HrefArgs`, under a comment saying it must be kept in step with `compilePattern` in `src/match.ts`, the runtime parser. It also adds `defineRoute` and `matchRoute` in `src/route.ts`, gives `href` two overloads whose rest parameter is `NoInfer<HrefArgs<Pattern>>`, and writes `docs/troubleshooting.md`, which shows that a misspelled parameter produces a TS2769 "No overload matches this call" error full of `Merge<{ storeId: string; } & { orderId: string; } & ...>` and an irrelevant second overload, and that a helper generic over the route doesn't compile without casting the params to `HrefArgs<P>`. The code works: tsc passes, and `href` and `matchRoute` return correct paths and params for required, optional, middle-optional and parameterless patterns, and the types reject missing, misspelled and unexpected parameters. A simpler design states the params per route (for example `defineRoute<{ storeId: string; orderId: string; tab?: string }>(...)`) or keeps `Record<string, string | undefined>`.
