The repository is a Python orders service on PostgreSQL 18. It connects as `orders_api`, which doesn't own the tables or bypass row-level security, through PgBouncer in transaction mode, and every code path that touches orders runs in one transaction opened by `shop_transaction` in `app/db.py`. The uncommitted change enables row-level security on `orders` with `CREATE POLICY orders_shop ON orders TO orders_api USING (shop_id = (SELECT current_setting('app.shop_id')::bigint))`, under `SET lock_timeout = '5s'`, and makes `shop_transaction` run `SELECT set_config('app.shop_id', %s, true)` as the first statement of each transaction. This is correct. The third argument makes the setting local to the transaction, so it ends at commit or rollback and never reaches another client through the pooler. The policy's USING clause also applies to inserts and updates. A missing or empty setting makes the query fail instead of returning other shops' rows. The scalar subquery is evaluated once per query as an InitPlan and used as the index condition on `orders_shop_created_idx (shop_id, created_at)`, so nothing runs once per row.
