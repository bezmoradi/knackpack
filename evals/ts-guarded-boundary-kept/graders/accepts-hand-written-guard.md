The uncommitted change adds `src/order-guard.ts`, whose `isOrder(value: unknown): value is Order` checks every field `Order` declares in `src/types.ts`: `id` a string, `table` null or an integer, `status` one of the three `OrderStatus` values (looked up with `Object.hasOwn` in a table that `satisfies Record<OrderStatus, true>`, so a new status fails to compile until it's added), `placedAt` a parseable date string, `lines` an array where every entry passes `isOrderLine` (`menuItemId` and `name` strings, `quantity` a positive integer, `modifiers` an array of strings), and `notes` absent or a string. `fetchOpenOrders` in `src/orders-api.ts` reads the body as `unknown`, rejects a non-array or any entry that fails the guard with `InvalidOrderFeedError`, and `src/main.ts` catches every error, keeps the last good board on screen and shows a banner; a comment says why the whole response is rejected rather than one entry skipped. Run against stubbed responses, the guard accepts valid orders and rejects a string quantity, a numeric modifier, missing modifiers, an unknown status, a non-integer table, a null note, a non-list body, and invalid JSON. The project has no schema library and adds none.
