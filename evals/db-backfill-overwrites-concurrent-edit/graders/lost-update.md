The repository is a Python service on PostgreSQL 17. Customers can edit their display name at any time, and every app instance already saves it in the nullable column `customers.display_name`. The uncommitted change adds scripts/backfill_display_name.py, which runs while the app serves customers. In each batch it runs `SELECT id, name FROM customers WHERE display_name IS NULL AND id > %s ORDER BY id LIMIT 1000`, then for each row it read runs `UPDATE customers SET display_name = %s WHERE id = %s` with the name it read, and commits the batch. The UPDATE doesn't check that display_name is still NULL, so a customer who sets a display name after the SELECT read their row and before the UPDATE reaches it has their choice overwritten with their old name; under PostgreSQL's default isolation the UPDATE even waits for the customer's uncommitted edit and then overwrites it.
