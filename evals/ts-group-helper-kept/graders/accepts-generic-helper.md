The uncommitted `src/collections.ts` adds `groupBy<T, K extends PropertyKey>(items: readonly T[], keyOf: (item: T) => K): Partial<Record<K, T[]>>`. Both type parameters carry information between input and output: `T` makes each group an array of the caller's item type, and `K` makes the result's keys the key function's return type, so `groupBy(tickets, (ticket) => ticket.status)` in `src/digest.ts` returns `Partial<Record<TicketStatus, Ticket[]>>` and reading a key that isn't a status is a compile error. `Partial` is accurate because only keys that occur are present, and callers handle the absent case (`?.length ?? 0`, a default in the destructuring). The result object has a null prototype, so keys such as `constructor` or `__proto__` group correctly. A doc comment says `Object.groupBy` isn't used because the project supports Node 18 (`engines` `>=18.18`, `lib` ES2022). tsc passes with `strict` and `noUncheckedIndexedAccess`, and the digest prints the right counts.
