The repository is an orders service on PostgreSQL 17 whose `orders` table has about 200 million rows and takes writes all day. Its migrations run with `alembic upgrade head` in the deploy pipeline, and migrations/env.py runs the revisions inside `with context.begin_transaction():`. The uncommitted change adds revision 0002, whose upgrade runs, inside `with op.get_context().autocommit_block():`, first `op.execute("SET lock_timeout = '5s'")` and then `op.create_index("ix_orders_tenant_created", "orders", ["tenant_id", "created_at"], postgresql_concurrently=True)`; its downgrade drops the index with `postgresql_concurrently=True` inside an autocommit block too. Alembic's `autocommit_block()` commits the migration's transaction before the block and runs the block's statements outside any transaction, which is what CREATE INDEX CONCURRENTLY and DROP INDEX CONCURRENTLY need, so the migration doesn't fail for running inside a transaction.
