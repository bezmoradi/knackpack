The repository is a Python catalog service on PostgreSQL 18. Each process caches prices in memory with no expiry. A trigger sends `NOTIFY price_changed` when a price changes, and a listener thread in each process (`app/listener.py`) takes a connection from the process's pool, sets autocommit, runs `LISTEN price_changed` and drops each notified product from its cache. The uncommitted change adds `deploy/pgbouncer.ini` with `pool_mode = transaction` and points `DATABASE_URL` in `deploy/app.env` at PgBouncer, so the pool, listener included, now connects through it. The listener isn't changed. PgBouncer's transaction pooling never supports `LISTEN`: the server connection that ran it goes back to the pool when that statement's transaction ends and serves other clients, so the listener stops receiving the notifications. The caches are then never invalidated and keep serving old prices.
